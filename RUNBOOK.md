# RUNBOOK

Step-by-step instructions to regenerate every artifact in this repository, from the raw CSV to the live dashboard.

> **Before you start:** two of the six notebooks (`processing_and_cleaning_week_3.ipynb` and `02_build_tables.ipynb`) were originally written in Google Colab and still contain hardcoded `/content/...` paths. They must be edited as described in Stage 1 before they will run locally. This is a known open item — see "Known Gaps" at the bottom.

## 0. Environment Setup

```bash
git clone https://github.com/SofiaGMiranda/BIG-DATA-FINAL-PROYECT-2025-01.git
cd BIG-DATA-FINAL-PROYECT-2025-01/project

python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r src/requirements.txt
```

All commands below assume your working directory is `BIG-DATA-FINAL-PROYECT-2025-01/project/` unless stated otherwise.

## 1. Preprocessing — `notebooks/processing_and_cleaning_week_3.ipynb`

**Input:** `data/raw/healthcare_dataset.csv`
**Output:** `data/interim/healthcare_processed.csv`

Before running, replace the hardcoded Colab path:

```diff
- df = pd.read_csv('/content/healthcare_dataset.csv')
+ df = pd.read_csv('../data/raw/healthcare_dataset.csv')
```

and at the end of the notebook, point the export at the repo's `data/interim/` folder instead of the notebook's working directory:

```diff
- df.to_csv('healthcare_processed.csv', index=False)
+ df.to_csv('../data/interim/healthcare_processed.csv', index=False)
```

Run all cells top to bottom (dedup, feature engineering, `Cost_Per_Day`, label decoding).

## 2. Build Relational Tables — `notebooks/02_build_tables.ipynb`

**Input:** `data/interim/healthcare_processed.csv`
**Output:** `data/processed/{patients,hospitals,doctors,medical_conditions,medications,medical_records}.csv`

Same fix needed at the top:

```diff
- df = pd.read_csv("/content/healthcare_processed.csv")
+ df = pd.read_csv("../data/interim/healthcare_processed.csv")
```

and each `to_csv("name.csv", ...)` call should write to `../data/processed/name.csv` instead of the notebook's local directory.

## 3. PCA / Dimensionality Reduction — `notebooks/week5_features and dimensinality_correcion.ipynb`

**Input:** `data/interim/healtcare_processedv2.csv`
**Output:** `data/processed/healthcare_pca.csv`

Reads directly from `../data/interim/healtcare_processedv2.csv` and `../data/processed/healthcare_pca.csv` — no path edits needed, run top to bottom.

## 4. Clustering — `notebooks/week7_clustering_validation.ipynb`

**Input:** `data/interim/healtcare_processedv2.csv`, `data/processed/healthcare_pca.csv`
**Output:** `data/processed/healthcare_pca_clusters.csv`, `artifacts/models/kmeans_model_final.pkl`

Runs K-Means and DBSCAN, validates with silhouette/Calinski-Harabasz, and persists the fitted K-Means model. No path edits needed.

## 5. Ranking Engine — `notebooks/week10_motor_priorizacion_cuidado_clinico_v2.ipynb`

**Input:** `data/interim/healtcare_processedv2.csv`, `data/processed/healthcare_pca_clusters.csv`
**Output:** `data/processed/ranking_prioridad_clinica.csv`

Trains the baselines, Logistic Regression, Random Forest, CatBoost, and the final ensemble; exports the ranked priority queue. No path edits needed.

## 6. Graph Analytics — `notebooks/weekf13_grapt.ipynb`

**Input:** `data/interim/healtcare_processedv2.csv`, `data/processed/healthcare_pca_clusters.csv`
**Output:** `artifacts/graph/clinical_graph.gexf`

Builds the lift-filtered condition↔medication bipartite graph and exports the GEXF file used by the dashboard. No path edits needed.

## 7. Run the Dashboard Locally

```bash
cd src
streamlit run app.py
```

You must launch from inside `src/` — `app.py` resolves data paths (`../data/...`) relative to the working directory, not the file location. Running `streamlit run src/app.py` from `project/` will fail to find the data files.

Live version (no local setup required): https://big-data-final-proyect-2025-01clinal-data.streamlit.app/

## Known Gaps

- **`healtcare_processedv2.csv` has no traceable source.** Stages 3–6 all read `data/interim/healtcare_processedv2.csv`, but no notebook in this repo writes that file — only `healthcare_processed.csv` (no "v2") is produced by Stage 1. The v2 file currently in `data/interim/` was committed directly rather than generated by a documented step. Until the transformation from v1 → v2 is captured in a notebook or script, the pipeline is not fully reproducible end-to-end from the raw CSV alone.
- **Stages 1–2 need manual path edits** (see above) before they'll run outside the original Colab environment — they aren't yet parameterized with `argparse` or relative-path resolution like `graph_utils.py` uses.
- **`build_graph.py` does not exist yet** as a standalone script — Stage 6 still requires opening and running the notebook rather than a CLI command, as already noted in the report's Limitations and Future Work section.
